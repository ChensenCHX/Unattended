# FacilityOpus

## 基本情報

| 項目 | 値 |
|------|-----|
| 資源 | Opus + 連鎖収穫 |
| 建設コスト | Opus 以外の全資源 |
| 退化先 | Empty |
| 建設前提 | 任意の区画 |
| 特別制限 | ワークスペース上に同時に 1 つのみ存在可能 |

## コアルール

FacilityOpus はワークスペースグリッド上で標準的な **B3/S23 コンウェイのライフゲーム**を実行します。

### 操作フロー

1. **初期化**：`interact_with("start")` で初期細胞状態テーブルを生成。施設自身と周囲 8 セルは常に 0。
2. **細胞編集**：`interact_with("add", x, y)` と `interact_with("remove", x, y)` で細胞を設定。各操作に Opus 1 消費。
3. **進化と検証**：`interact_with("eval")` で 1 ステップ進化し、実際の施設配置が進化結果と一致するか検証。

### 終了と報酬

Opus の周囲 8 セルに建築物があると終了状態に入ります。それらの建築物の種別と Age が記録され、収穫時に Age で重み付けされた連鎖報酬が得られます。

## 戦略のヒント

- B3/S23 ルールの理解：生存細胞は隣接 2 または 3 で生存継続、死細胞は隣接 3 で誕生
- 細胞 Age は 0 から開始。`add` で追加された細胞の Age は 0
- 進化で出現した細胞の Age は隣接 3 細胞の Age 平均（切り捨て）
- セルオートマトンと反復進化の理解が試される

## インタラクションメソッド

| メソッド | シグネチャ | 説明 |
|----------|-----------|------|
| `start` | `start() → table?` | 初期状態テーブルを生成（1=建築物, 0=空） |
| `eval` | `eval() → bool` | 1 ステップ進化し、配置を検証 |
| `add` | `add(int x, int y) → bool` | 座標の細胞を 1 に設定、Opus 1 消費 |
| `remove` | `remove(int x, int y) → bool` | 座標の細胞を 0 に設定、Opus 消費 |
