# FacilityOpus

## 基本信息

| 项目 | 说明 |
|------|------|
| 产出资源 | Opus，以及连锁产出 |
| 建造消耗 | 除 Opus 外的全部资源 |
| 收获后退化 | Empty |
| 建造前置 | 任意地块 |
| 特殊限制 | 场上同时最多存在一个 |

## 核心规则

FacilityOpus 在工作空间网格上执行标准的 **B3/S23 康威生命游戏** 规则。

### 操作流程

1. **初始化**：调用 `interact_with("start")` 生成初始细胞状态表并返回给玩家。设施自身及其周围一圈的细胞初始为 0。
2. **编辑细胞**：通过 `interact_with("add", x, y)` 和 `interact_with("remove", x, y)` 设置细胞状态，每次操作消耗 1 个 Opus 资源。
3. **演化验证**：调用 `interact_with("eval")` 执行一步演化并检查场地上的建筑分布是否与演化结果一致。

### 终结与收益

当 Opus 周围一圈（八格）有建筑时，设施进入终结状态。此时会记录周围建筑的种类和持续存活轮数（Age），收获时按照 Age 加权的公式计算连锁产出。

## 策略提示

- 需要精确理解 B3/S23 规则：当前存活且邻居数 2 或 3 时继续存活，当前死亡且邻居数恰好 3 时复活
- 细胞存活轮数（Age）从 0 开始累计，通过 `add` 添加的细胞 Age 从 0 起始
- 新演化出现的细胞 Age 取周围三个细胞 Age 的平均值向下取整
- 考察玩家对细胞自动机规则和迭代演化过程的理解

## 交互接口

| 方法 | 签名 | 说明 |
|------|------|------|
| `start` | `start() → table?` | 生成初始状态表，返回 table 中 1=有建筑 0=无建筑 |
| `eval` | `eval() → bool` | 执行一步生命游戏演化并验证场地分布，返回是否符合预期 |
| `add` | `add(int x, int y) → bool` | 将指定坐标设为 1，消耗 1 Opus |
| `remove` | `remove(int x, int y) → bool` | 将指定坐标设为 0，消耗 Opus |
